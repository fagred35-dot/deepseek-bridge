P0 — реально мешало
1. screenshot { window } нестабилен
Пять раз из семи ловил не то окно (Chrome, Discord, «Волна») при том, что нужное было в list_windows с точным заголовком. Приходилось либо снимать весь экран, либо угадывать заголовок заново.
Помогло бы:

screenshot { process: "spo-watcher" } — по имени процесса, не по title;

force-foreground: активировать окно перед снимком (SetForegroundWindow);

матчинг по подстроке без учёта регистра;

либо window_id (HWND), который вернул list_windows — сейчас его там нет.

2. edit_many падает с EARGS
При edits: [{...}, {...}] — «Правка #1: old не может быть пустой». Первый объект массива теряется. В MEMORY уже помечено как грабля, но фикс бы сэкономил половину вызовов. Гипотеза: парсер JSON-аргумента не любит массив объектов в этом поле, или ключ edits мапится не так.

3. Потеря/перемешивание результатов при нескольких вызовах в сообщении
Несколько раз результат вообще не пришёл (повторял), и почти всегда порядок результатов не совпадал с порядком блоков. Опасно: можно спутать grep по одному файлу с другим. Даже с подписью "path" в ответе — лишний риск.
Помогло бы: сохранять порядок, либо явный call_id, который я передаю и получаю обратно.

P1 — заметно тормозило
4. git add + git commit в одном сообщении — race
add проходит, commit говорит «nothing to commit», повтор помогает. Похоже на рассинхрон индекса. Или явное «вызовы в одном блоке выполняются строго последовательно» в доке — но на практике нет.

5. run_command + пайп в cmd = пустой stdout
dotnet build | findstr вернул пустоту (cp866), пришлось писать в build.log и читать. Это не баг моста, но подсказка «на Windows: редирект в файл, потом read_lines { encoding: "auto" }» в описании инструмента спасла бы.

6. Автоопределение кодировки по умолчанию
read_file по умолчанию UTF-8, для старых Windows-файлов — мусор. encoding: "auto" есть, но его надо знать. Может, авто по BOM + эвристика на кириллицу, а в ответе поле detectedEncoding — всегда.

7. list_dir без mtime
Пришлось дёргать stat на каждый файл. Опциональный withStat: true — и половина моих вызовов в этой сессии не нужна.

8. process_logs упомянут в подсказках, но нет в списке инструментов
Для отладки start_process нужен хвост stdout/stderr. list_processes даёт stdoutTail, но без process_logs я не могу подождать и перечитать.

P2 — приятно иметь
9. diff двух произвольных файлов — есть только git diff. Сравнить две версии конфига или два скрина — руками.

10. file_info / image_info — упомянуты в ошибках (EIMAGE), но не в реестре. Для PNG хочется width/height/размер, для exe — версия/архитектура.

11. batch — в лимитах «batch до 50», но как отдельного инструмента его нет. Если он есть неявно (несколько dsbridge подряд) — ок, тогда просто убрать упоминание «batch» из текста про лимиты, чтобы не путало.

12. edit_file и CRLF
read_file отдаёт \n, файл на диске может быть \r\n — old_string не совпадает, ENOMATCH. Нормализация line endings на входе спасла бы. Сейчас спасает edit_many { dry_run }... но он падает (см. п.2).
