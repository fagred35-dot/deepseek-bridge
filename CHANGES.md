## 19.09.2026 — инструкция для модели v2: список инструментов генерируется из реестра

**Главное:** список инструментов в промте больше не дублируется руками. Расширение забирает
его у моста (`/api/tools`) в момент нажатия кнопки «Вставить инструкцию для модели», поэтому
промт физически не может разъехаться с `TOOLS`. Раньше он отставал: новые инструменты
(`diff`, `batch`, `remember`, `process_logs`, `read_around`…) в инструкции не появлялись.

Текст разбит на три части в `extension/content.js`:
- `INSTRUCTION_INTRO` — формат вызова, сколько вызовов за сообщение, раздел «ЗРЕНИЕ»;
- список инструментов — собирается функцией `buildToolList()` по группам `TOOL_GROUPS`;
- `INSTRUCTION_OUTRO` — «вместо `run_command` лучше…», что не делать молча, особенности Windows,
  флаги моста, коды ошибок, память между чатами, рабочие процессы.

Инструмент, которого нет ни в одной группе, попадает в «Прочее» — потеряться не может.
Если мост не ответил, инструкция всё равно вставляется: со списком из имён
(`FALLBACK_TOOL_NAMES`) и пометкой, что подробности недоступны.

Новое в тексте (сверх того, что было):
- таблица «вместо `run_command` → специализированный инструмент» (без флага «Выполнение команд»);
- раздел «когда НЕ действовать молча» — необратимое только по явной просьбе;
- полная таблица кодов ошибок, включая `ENOMATCH`, `ERESERVED`, `EBATCHNEST`, `ELIMIT`;
- **предупреждение про `taskkill /F /IM node.exe`** — им модель однажды убила сам мост;
  раньше в инструкции его не было;
- рабочие процессы (правка файла, отладка сервера, сборка проекта).

**Исправлены устаревшие факты из черновика v2** (проверено по коду):
- `%Path%` в `env` **раскрывается** (`expandEnvValues`, сделано в wishlist3 1.6) — в черновике
  было «не раскрывается»;
- зарезервированные имена Windows: `stat` и `read_file` читают такие файлы штатно, не работают
  только создание / переименование / удаление → `ERESERVED`;
- `dsbridge-image` — **не единственный** способ увидеть результат: скриншоты из `screenshot`
  расширение прикрепляет автоматически;
- значения в памяти **не обрезаются**, лимит только на число ключей (500).

Тесты: `extension/test.mjs` — **34 → 49** проверок. Тест импортирует настоящий `TOOLS`
из `bridge/src/tools.mjs` и сверяет с ним собранный список: если инструмент не доедет
до промта, тест упадёт. Расширение — 0.9.0.

## 19.09.2026 — wishlist3, часть 2: batch, память, метрики, логи, read_around

**Главное:** третий список закрыт почти целиком. Инструментов стало **40** (было 33),
тестов — **197** (было 168). Остались только 1.1 (обход зарезервированных имён — на этой машине
не подтвердился), 2.6 (интерактивный браузер по CDP) и 3.6 (ASCII-превью скриншота).

Новые инструменты:
- `batch { calls: [{ tool, args }] }` — до 50 инструментов за один round-trip, результаты в том же
  порядке. `stopOnError: true` — остановиться на первой ошибке; по умолчанию ошибка одного вызова
  не мешает остальным, в ответе `failed` и `{ ok: false, error }` на своём месте. `batch` внутри
  `batch` запрещён (`EBATCHNEST`). Каждый под-вызов считается в `usage_stats` сам по себе.
- `remember` / `recall` / `forget` — память модели между сессиями в `~/.dsbridge/memory.json`.
  `ttl` в секундах, поиск по `pattern`, лимит 500 ключей, просроченное вычищается при чтении
  (`expiredRemoved`), `forget { all: true }` стирает всё.
- `usage_stats { sort, limit, reset }` — по каждому инструменту `calls` / `errors` / `totalMs` /
  `avgMs` / `maxMs` / `lastAt`, плюс `totals` и `uptimeSec`.
- `process_logs { pid|name, tail, since, waitMs, clear }` — вывод фоновых процессов. `since`
  принимает `nextOffset` из прошлого ответа (число для `stdout` или объект `{ stdout, stderr }`),
  `waitMs` — аналог `tail -f` (до 30 с), `clear` чистит буфер. Если буфер обрезался сверху —
  честный флаг `truncated: true` и сброс курсора, а не молчаливая пустота.
- `read_around { path, pattern, before, after, hit }` — широкий кусок файла вокруг вхождения:
  `matches` (сколько всего), `matchesAt` (номера строк), окно по 20 строк по умолчанию (до 500).

Внутри:
- `runTool` разделён на `runToolInner` (switch) и обёртку с таймингом — метрики пишутся в одном
  месте, а не в каждом `case`.
- `recordUsage()` + `readMemoryFile()` / `writeMemoryFile()` в `bridge/src/tools.mjs`.

Проверено: `NODE_OPTIONS= CODEBUDDY_SAFE_DELETE_ENABLED=0 node test.mjs` → **197 ok, 0 fail**.

**Грабли (не про мост):** два параллельных `Edit` по одному файлу — гонка read-modify-write,
второй молча терялся. Оба раза симптом один: правка «успешно применена», а в файле её нет.
Правки одного файла делать последовательно.

## 19.09.2026 — wishlist3: diff, image_info, find_tool, кодировки, dry_run, опции скриншота

**Главное:** закрыта большая часть третьего списка пожеланий DeepSeek. Инструментов стало
**33** (было 29), тестов — **168** (было 151).

Новые инструменты:
- `diff { pathA, pathB }` — unified-diff двух файлов своим LCS-алгоритмом, без зависимостей
  (`added` / `removed` / `same` / `hunks` + текст с ханками). Для очень больших файлов таблицу
  не строит, а честно помечает всё как удалённое+добавленное.
- `diff_git { path, rev }` — `git diff` по файлу (рабочее дерево или относительно ревизии).
- `image_info { path }` — формат и размеры png / jpeg / gif / bmp / webp из заголовка, без библиотек.
- `find_tool { name }` — ищет программу в `PATH` и стандартных местах установки (Program Files,
  LOCALAPPDATA, `%USERPROFILE%\.workbuddy-ai\binaries\<name>\versions`), даже если её нет в `PATH`.

Новые опции существующих инструментов:
- `read_file { encoding }` — `auto` определяет кодировку (BOM, строгий UTF-8, эвристика
  cp1251↔cp866); в ответе поле `encoding`.
- `edit_many { dry_run: true }` — показать, что нашлось бы, не меняя файл.
- `list_dir { recursive, maxDepth, glob }` — плоский обход с фильтром имён.
- `write_file { createDirs: false }` — падать, если папки нет (защита от опечатки в пути).
- `screenshot { fullPage, dark, device }` — высокий кадр, тёмная тема, пресеты устройства;
  снят прежний потолок высоты 2160 (теперь до 12000).
- `run_command` / `start_process`: в значениях `env` раскрываются `%VAR%` и `${VAR}` —
  `"%Path%"` теперь работает как ожидается.

Зарезервированные имена Windows (`nul`, `con`, …): `delete` / `move` / `copy` распознают такое
имя, пробуют обход через PowerShell и отдают `ERESERVED` с подсказкой вместо сырого `EPERM`.
Проверил: на этой машине создать/переименовать такой файл нельзя ни через Node, ни через
.NET / PowerShell, и `\\?\` не помогает — поэтому обход не подтверждён, а тест проверяет, что
мост не падает и отвечает внятной ошибкой.

Инструкция для модели (`extension/content.js`) расширена: явно про «зрение» (скриншоты и
локальные `dsbridge-image` прикрепляются к чату), новые инструменты и опции, раскрытие `env`,
зарезервированные имена и поведение при `EBRIDGE`. Версия расширения — **0.7.0**.

Проверено: `bridge/test.mjs` — **168 ok / 0 fail** (в изоляции, с `NODE_OPTIONS=`), синтаксис
всех модулей чистый.

Не сделано из списка: `process_logs` с follow, `remember` / `recall`, интерактивный браузер (CDP),
`batch`, `usage_stats`, чтение «вокруг паттерна», `screenshot.selector`.

## 19.09.2026 — exe-сборка: бандлер и самопроверка

**Главное:** `dsbridge.exe` не запускался вообще. `build.mjs` клал в SEA-блоб `src/server.mjs`
как есть, а SEA исполняет главный скрипт как **CommonJS** — падение на первой же строке
(`SyntaxError: Cannot use import statement outside a module`). Плюс exe читал `public/index.html`
и `scripts/screenshot.ps1` с диска рядом с собой, то есть вне проекта не работал.

Что сделано:

- `bridge/build.mjs` — свой мини-бандлер ESM→CJS (~80 строк): `import ... from`, побочные
  `import '...'`, `export const|let|var|function|class`, `import.meta.url` → `__importMetaUrl`.
  На неподдерживаемом экспорте падает с ошибкой, а не собирает молча сломанный файл.
- `bridge/src/assets.mjs` — новый модуль: единственное место, где код знает о файлах проекта
  (`getIndexHtml()`, `screenshotScriptPath()`). В exe-режиме сборка подменяет его исходник
  целиком: html вшит строкой, а `screenshot.ps1` распаковывается в `os.tmpdir()` при первом
  обращении (его нельзя вшить — он запускается как файл).
- `bridge/src/server.mjs` — `PUBLIC_DIR` убран, UI отдаётся через `getIndexHtml()`.
- `bridge/src/tools.mjs` — `SCRIPTS_DIR` убран, `list_windows` / `screenshot` берут путь
  через `screenshotScriptPath()`.
- `bridge/build.mjs` — шаг «4/4»: сборка сама проверяет результат. Копирует exe в чистую
  временную папку, запускает без файлов проекта и дёргает `/api/health`, `GET /`
  (вшитый html + подстановка токена), `write_file`/`read_file`, `sysinfo`, `list_windows`
  (то есть вшитый `screenshot.ps1`). Провал — сборка падает с кодом 1. Флаг `--no-verify`.
  `EBUSY` при копировании node.exe переводится в понятное «закрой запущенный dsbridge.exe».

Проверено: `bridge/test.mjs` — 151 ok / 0 fail, `extension/test.mjs` — 34 ok / 0 fail,
`node build.mjs` — зелёная самопроверка (`health`, UI, write/read, sysinfo, `list_windows`
на 7 окнах). Итог — `bridge/dist/dsbridge.exe`, 83,3 МБ, работает из папки без исходников.

**Важно:** встроенная проверка не зря — она дважды поймала реальные ошибки (подменённый
`assets.mjs` вставлялся в бандл как ESM, минуя трансформер; и исключённый из карты модулей
`assets.mjs` уронил бы `__require`). Обе нашлись только на запущенном exe.

**Не сделано:** `dist/Дипсик-Мост.zip` (собран 17:34) содержит **старые** исходники — в нём
нет `src/assets.mjs` и прежний сломанный `build.mjs`. Архив не пересобирался: релизы Brick
публикует сам. Если он уйдёт наружу в таком виде — у получателя exe не соберётся.

## 19.09.2026 — `extraRoots` (расширение 0.5.0)
