# План проекта: «Дипсик Мост»

Мост между веб-чатом DeepSeek (https://chat.deepseek.com/) и локальной файловой системой.
Выбранная стратегия интеграции — **A: браузерное расширение**.

---

## 0. Суть

Локальное приложение (в перспективе — один exe) поднимает на `127.0.0.1` HTTP-мост с набором
файловых инструментов и открывает UI-окно со статусом. Расширение для браузера, встроенное в
страницу `chat.deepseek.com`, перехватывает «вызовы инструментов» из ответов модели, выполняет
их через мост и возвращает результат обратно в чат.

## 1. Почему Стратегия A и в чём её цена

`chat.deepseek.com` — закрытый фронтенд: у него нет публичного native tool-calling и нет MCP-сервера,
к которому можно подключиться извне. Поэтому «дать чату инструменты» можно только через расширение,
которое:
- добавляет на страницу чата панель и слушает новые сообщения ассистента;
- распознаёт вызов инструмента по согласованному формату (fenced-блок с языком `dsbridge`);
- выполняет вызов через локальный мост;
- возвращает результат в чат.

**Плюс:** работаем в родном веб-чате, ничего не переписываем.
**Минус:** зависимость от DOM DeepSeek — при редизайне сайта селекторы/разметка могут поехать.
Поэтому весь код парсинга изолирован в одном модуле и написан защитно.

Альтернатива (Стратегия B — локальный клиент на API DeepSeek с `function calling`) надёжнее, но это
уже не веб-чат, а свой интерфейс. Оставлена как запасной путь.

## 2. Архитектура

```
Браузер (chat.deepseek.com)          Локальный мост (exe)              Файловая система
┌───────────────────────────┐        ┌──────────────────────────┐      ┌──────────────────┐
│ чат DeepSeek              │  1     │ HTTP/WS сервер :8443     │  2   │ рабочая папка    │
│ content script (панель)   │ ─────► │ движок инструментов      │ ───► │ (path jail)      │
│ background service worker │ ◄───── │ модуль безопасности      │ ◄─── │ .trash, audit    │
└───────────────────────────┘   4    │ конфиг / состояние       │  3   └──────────────────┘
                                     └────────────┬─────────────┘
                                                  │ события/статус
                                     ┌────────────▼─────────────┐
                                     │ UI-окно (Tauri/Electron) │
                                     │ папка · статус · лог     │
                                     └──────────────────────────┘
```

Поток вызова инструмента:
1. Модель выводит блок `dsbridge` с JSON-вызовом.
2. content script распознаёт вызов → background service worker → `POST /api/tool`.
3. Мост проверяет токен и path jail, выполняет операцию над ФС.
4. Результат возвращается в чат (карточка + кнопка «вставить в чат»), событие уходит в UI.

## 3. Компоненты

| Компонент | Ответственность | Технология |
|---|---|---|
| **Bridge Server** | HTTP API на localhost, роутинг, SSE-события, отдача UI | Node.js (только stdlib) |
| **File Tool Engine** | Реализация инструментов, нормализация путей | Node.js |
| **Security** | Токен, path jail, корзина `.trash`, audit-log, allow-list origin | Node.js |
| **UI-окно** | Папка, статус подключения, список инструментов, лента активности | HTML/CSS/JS (в перспективе Tauri) |
| **Extension: background SW** | Единственная точка доступа к мосту (обходит CORS через host_permissions) | MV3 Service Worker |
| **Extension: content script** | Панель в чате, парсинг вызовов, вставка результата | MV3 Content Script |
| **Extension: popup** | Ввод/хранение токена, статус | MV3 Popup |
| **Config / Audit** | `~/.dsbridge/config.json`, `~/.dsbridge/audit.log` | Node.js |

## 4. Форматы обмена данными

### 4.1 API моста (localhost)

| Метод | Путь | Назначение | Auth |
|---|---|---|---|
| GET | `/api/health` | статус, версия, рабочая папка | — |
| GET | `/api/tools` | список инструментов и схем | токен |
| POST | `/api/tool` | выполнить инструмент | токен |
| GET | `/api/events` | SSE-поток событий/логов | токен |
| POST | `/api/open` | открыть рабочую папку в проводнике | токен |
| GET | `/` | UI-страница | — (токен вшит в HTML) |

Авторизация: заголовок `X-Bridge-Token: <token>` либо `?token=` для SSE.

### 4.2 Запрос инструмента

```json
{ "tool": "read_file", "args": { "path": "notes.md" } }
```

### 4.3 Ответ

```json
{ "ok": true, "tool": "read_file", "result": { "path": "notes.md", "bytes": 1234, "content": "..." } }
```
```json
{ "ok": false, "tool": "read_file", "error": { "code": "EPATHJAIL", "message": "Путь вне рабочей папки" } }
```

### 4.4 Формат вызова для модели (контракт расширения)

Модели сообщается, что инструмент вызывается одним fenced-блоком с языком `dsbridge`:

```dsbridge
{ "tool": "list_dir", "args": { "path": "." } }
```

Правила: один вызов на сообщение, дождаться результата перед следующим.

## 5. Инструменты v1

| Инструмент | Аргументы | Что делает |
|---|---|---|
| `list_dir` | `path` | список файлов и папок |
| `read_file` | `path` | чтение текстового файла (с лимитом) |
| `write_file` | `path`, `content`, `mode` (overwrite/append) | запись файла |
| `make_dir` | `path` | создать папку |
| `move` | `from`, `to` | переместить/переименовать |
| `delete` | `path` | удалить (в `.trash`, не безвозвратно) |
| `stat` | `path` | тип, размер, даты |
| `search` | `query`, `path` | поиск по имени и содержимому |

## 6. Безопасность

- **Токен** обязателен для всех операций; сравнение через `timingSafeEqual`.
- **Path jail** — все пути резолвятся внутри рабочей папки; выход за её пределы → `EPATHJAIL`.
- **Корзина** — `delete` перемещает в `<workspace>/.trash`, а не удаляет.
- **Audit-log** — каждый вызов пишется в `~/.dsbridge/audit.log` и уходит в ленту UI.
- **Origin allow-list** — CORS разрешён только для `chat.deepseek.com` и `chrome-extension://`.
- **localhost only** — сервер слушает `127.0.0.1`, наружу не публикуется.

## 7. Структура UI

**UI-окно моста** (страница `/`):
- Шапка: название, индикатор статуса, версия.
- Карточка «Рабочая папка»: путь + кнопка «Открыть».
- Карточка «Подключение»: порт, токен (скрыт, кнопка «Копировать»).
- Карточка «Инструменты»: список доступных инструментов.
- Лента активности: живые события через SSE.
- Блок «Инструкция для модели» с кнопкой копирования.

**Панель расширения в чате** (плавающая, справа снизу):
- индикатор связи с мостом;
- переключатель «авто-выполнение»;
- кнопка «Вставить инструкцию для модели»;
- лог выполненных вызовов;
- карточки результатов у сообщений с кнопкой «Вставить результат в чат».

## 9. Риски и открытые вопросы

1. **Хрупкость DOM DeepSeek** — основной риск; весь парсинг изолирован в `content.js`.
2. **Вставка в поле ввода** — DeepSeek использует React-контролируемое поле; реализован
   «нативный» сеттер значения + событие `input`. Требует проверки на живом сайте.
3. **Дубли вызовов при стриминге** — защита: флаг на элементе + дедуп по подписи вызова.
4. **Один exe** — упаковка через Node SEA; UI открывается в браузере (нативный webview — позже).
5. **Токен в HTML** — приемлемо для localhost; при выходе за localhost обязателен HTTPS.
